# GETLINK Tạp hóa — TAPHOA Order/Debt Parity Spec

## Goal
Complete GETLINK's existing Tạp hóa sales workflow so it matches the proven TAPHOA business flow without creating a second sales system and without changing Chat authentication/session rules.

## Locked core
- Keep `getlink_sales_orders`, `getlink_sales_order_items`, `getlink_debt_ledger` as the only GETLINK sales/debt core.
- Keep Chat JWT as identity; no GETLINK login.
- Keep User scoped to own orders/debt; Admin manages all customers/orders/debt.
- Keep order number generated by the existing `order_no` identity column.
- Keep `pending -> delivered -> returned` state model.
- `Xóa` pending means delete the pending order.
- `Xóa` delivered means return/reverse the delivered order and reverse debt; it must not physically delete the delivered record.

## Bán hàng
Existing product search and cart remain owner of selection. The work surface must support:
- Search product, choose quantity, edit quantity, remove product, clear current cart.
- Quick preview of selected order before submit/approve.
- Submit creates Pending order with `#order_no`.
- Admin quick sale creates Delivered order immediately.
- Edit Pending loads the same order back into Tạp hóa and updates the same order id/order number.
- Edit Delivered loads the same order back into Tạp hóa; update keeps status Delivered and reconciles the order-linked debt amount to the new total.
- Cancel edit restores normal cart mode without creating a new order.

## Đơn hàng
Orders need both lifecycle views and operational reporting:
- Lifecycle: Pending, Delivered, Returned.
- Filter/report by Today and custom date range; quick ranges Yesterday, This week, This month, This year.
- Search by customer, order number, or product.
- Summary by source for the filtered orders: source, quantity, cost, revenue, profit.
- Source detail: rows by order/customer/product/quantity.
- Source combined view: group same product and sum quantity.
- Share source detail or combined summary through native share when supported; fallback copy text.
- Pending: view, edit, deliver (Admin), delete, delete all in current pending scope.
- Delivered: view, edit (Admin), return/delete semantic (Admin), return all delivered in the current filtered scope after destructive confirmation.
- Returned remains read-only history.

## Công nợ
- Admin sees debt customer list; User sees own debt directly.
- Customer detail shows running ledger and balance after each transaction.
- Any ledger row linked to an order opens that order detail.
- From debt-linked order detail, allowed lifecycle actions are the same as from Orders: Pending may edit/delete; Delivered Admin may edit/return. User cannot mutate another customer's order and cannot perform Admin-only lifecycle actions.
- Order/debt changes refresh through the existing GETLINK sync mechanism.

## UI constraints
- Keep the current GETLINK visual system and the UI polish already merged.
- Mobile-first, 44px important touch targets, dense operational layout.
- Do not add a new full-screen app or duplicate manager owner.
- Reporting/source drill-down lives inside the existing order manager.
- Destructive actions require confirmation; ordinary drill-down does not.

## Out of scope
- Chat/Call code, Chat session policy, Supabase Auth lifecycle.
- Supermarket crawler/search logic, News, TAPHOAXYZ runtime/database.
- New sales tables or migration of legacy TAPHOA data.
